QMAS Design System — Mandatory Instructions

You are building UI for QMAS, built on Ant Design v6 with a custom Figma design system. These instructions are mandatory — every rule must be followed on every response without exception.

Critical lesson — how tokens actually work in Figma

This is the most important section. Read before writing any Figma plugin code.

❌ WRONG — hardcoding values (detaches from design system)

// FORBIDDEN — hardcoding fontSize, fontWeight, fontName
node.fontSize = 14;
node.fontWeight = 600;
node.fontName = { family: 'Roboto', style: 'Bold' };
node.fills = [{ type: 'SOLID', color: { r: 0, g: 0, b: 0 } }];

This breaks the design system. If tokens change, these nodes will not update automatically.

✅ CORRECT — binding to tokens (stays connected to design system)

// REQUIRED — bind text style by ID
const styles = await figma.getLocalTextStylesAsync();
const baseStrong = styles.find(s => s.name === 'Base/Strong');
await node.setTextStyleIdAsync(baseStrong.id);
// ↑ fontName, fontSize, lineHeight all come from the style — never override after this

// REQUIRED — bind color variable
const vars = await figma.variables.getLocalVariablesAsync();
const colorText = vars.find(v => v.name === 'colorText');
figma.variables.setBoundVariableForPaint(
  node.fills[0],
  'color',
  colorText
);
// ↑ Never write RGB values directly

Rules that follow from this

  1. Never override fontName after calling setTextStyleIdAsync() — doing so detaches the style binding and hardcodes the font.
  2. Never write RGB/hex directly — always use setBoundVariableForPaint() with the variable.
  3. Font is Roboto — it comes from the text style binding, not from manual fontName assignment. Do not load or assign fonts manually.
  4. The values in the Text Style table below are for human reference only — in Figma plugin code, always bind by style ID, not by reproducing the values.

STEP 0 — Before writing any code, answer these questions

For Figma plugin code: 1. Does the QMAS file already have this component? → Use findOne() + createInstance(). Never build from scratch. 2. Which QMAS Text Style applies? → Bind with setTextStyleIdAsync(). Never set fontSize/fontWeight manually. 3. Which QMAS Color Variable applies? → Bind with setBoundVariableForPaint(). Never write hex/RGB. 4. Which QMAS Effect Style applies? → Bind with setEffectStyleIdAsync(). Never write custom boxShadow. 5. Never override any bound property after binding — that detaches the token.

For React code: 1. Does Ant Design v6 have a component for this? → Use <Button>, <Input>, <Card> etc. Never use raw HTML. 2. Which QMAS Text Style applies? → Apply fontSize + lineHeight + fontWeight together with comment. 3. Which color token applies? → Use token value with comment. Never raw hex.

MANDATORY RULE 0 — Use existing QMAS components first (Figma plugin)

This is the highest priority rule for Figma plugin code.

NEVER build a component from scratch using frames + fills + text nodes. The QMAS file already has fully-built, token-bound components. Always use them.

❌ FORBIDDEN — building from scratch

// WRONG — hardcoded frame, not connected to design system
const btn = figma.createFrame();
btn.fills = [{ type: 'SOLID', color: { r: 0.09, g: 0.47, b: 1 } }];
btn.cornerRadius = 6;
const label = figma.createText();
label.characters = 'Save';

✅ REQUIRED — import the right component set, then instantiate

QMAS publishes three separate Button component sets, not one set with Type=Primary/Default/Danger variants. Pick the right key for the role you want.

// Published library keys (Ant Design System - v6 (QMAS))
const QMAS_BUTTON_KEYS = {
  Primary: 'ea1bf5e1a1938d5470bab8292dcaa51ed0dd290a',  // → main CTA
  Default: '513ffe289cdcf781eaf16e30543226c93ee91aae',  // → secondary
  Danger:  '25cd90c98741332e44ef4b26c9e3b422d5dc9b92',  // → destructive
};

// STEP 1 — Import the set from the team library
const primarySet = await figma.importComponentSetByKeyAsync(QMAS_BUTTON_KEYS.Primary);

// STEP 2 — Pick its default variant (or another variant by name)
const variant = primarySet.defaultVariant ?? (primarySet.children[0] as ComponentNode);

// STEP 3 — Create instance (inherits ALL token bindings)
const btn = variant.createInstance();
btn.setProperties({ Label: 'Save' });  // case-sensitive — try Label / label / text if unsure
figma.currentPage.appendChild(btn);

✅ createInstance() Yes — inherits from component Yes
❌ Manual frame + fills No — hardcoded No

MANDATORY RULE 2 — QMAS Text Styles (bind, never hardcode)

In Figma plugin code — always bind by style ID

async function applyTextStyle(node: TextNode, styleName: string) {
  const styles = await figma.getLocalTextStylesAsync();
  const style = styles.find(s => s.name === styleName);
  if (!style) throw new Error(`Text style "${styleName}" not found`);
  await node.setTextStyleIdAsync(style.id);
  // ✅ Done. Do NOT set fontName, fontSize, lineHeight after this.
}

// Usage
await applyTextStyle(titleNode, 'Heading/2');
await applyTextStyle(bodyNode, 'Base/Regular');
await applyTextStyle(captionNode, 'Small/Regular');

MANDATORY RULE 3 — QMAS Color Variables (bind, never hardcode)

In Figma plugin code — always bind by variable

async function applyColorVariable(node: SceneNode, variableName: string) {
  const vars = await figma.variables.getLocalVariablesAsync();
  const variable = vars.find(v => v.name === variableName);
  if (!variable) throw new Error(`Variable "${variableName}" not found`);

  const collection = await figma.variables.getVariableCollectionByIdAsync(
    variable.variableCollectionId
  );

  // For fills
  if ('fills' in node) {
    const fills = JSON.parse(JSON.stringify(node.fills));
    fills[0] = figma.variables.setBoundVariableForPaint(
      fills[0],
      'color',
      variable
    );
    node.fills = fills;
  }
}

// Usage
await applyColorVariable(textNode, 'colorText');
await applyColorVariable(frameNode, 'colorBgLayout');
await applyColorVariable(cardNode, 'colorBgContainer');

MANDATORY RULE 4 — QMAS Effect Styles (bind, never hardcode)

In Figma plugin code — bind by style ID

async function applyEffectStyle(node: SceneNode, styleName: string) {
  const styles = await figma.getLocalEffectStylesAsync();
  const style = styles.find(s => s.name === styleName);
  if (!style) throw new Error(`Effect style "${styleName}" not found`);
  node.effectStyleId = style.id;
  // ✅ Done. Do NOT set custom boxShadow after this.
}

// Usage
await applyEffectStyle(cardNode, 'boxShadowCard');
await applyEffectStyle(modalNode, 'boxShadow');
await applyEffectStyle(dropdownNode, 'boxShadowSecondary');

Effect style reference

boxShadowCard             → Cards
boxShadow                 → Modals, Drawers
boxShadowSecondary        → Dropdowns, Popovers, Tooltips
boxShadowTertiary         → Subtle elevation
boxShadowButtonPrimary    → Primary button (Ant applies automatically)
boxShadowButtonDefault    → Default button (Ant applies automatically)
boxShadowButtonError      → Danger button (Ant applies automatically)

Note: Focus state shadows (focusPrimary / focusError / focusWarning) are not exposed as separate effect styles in this library — they're baked into each component's variants. Don't try to apply them by name.

MANDATORY RULE 5 — Spacing (8px grid)

4px  → icon-to-text inside tag/badge       (marginXXS)
8px  → icon-to-text, tight list items      (marginXS)
16px → button group, sibling components    (margin)   ← DEFAULT
24px → standard card padding, section gap  (marginLG)
32px → major section break only            (marginXL)

Dashboard / data-heavy cards → 16px padding (NOT 24px)
Standard page cards          → 24px padding
Table card                   → 0px (Table owns its borders)

MANDATORY RULE 6 — Border Radius (two-tier, never override)

6px → Interactive: Button, Input, Select, Dropdown   (borderRadius)
8px → Container:  Card, Modal, Panel, Drawer          (borderRadiusLG)
4px → Dense controls                                  (borderRadiusSM)
2px → Tags, badges                                    (borderRadiusXS)

ConfigProvider sets these. Never override with custom values.

MANDATORY RULE 7 — Three-layer surface

Layer 3: #FFFFFF + boxShadow           → Modal, Dropdown, Tooltip
Layer 2: #FFFFFF + 1px #F0F0F0 border  → Card
Layer 1: #F5F5F5                       → Page canvas (colorBgLayout)

Never put white cards on a white page background.

MANDATORY RULE 8 — Primary button = main CTA (UX rule)

When a page or modal has multiple buttons, the most important call-to-action MUST use the Primary button (type="primary"). This is a UX requirement — it tells the user exactly what to click next.

The rule in full

  • One Primary button per screen / modal — the single most important action
  • Primary button = the CTA — Save, Submit, Create, Confirm, Next
  • All other buttons = secondary — use default, link, or text
  • Never leave a page with multiple buttons where none is Primary — the user won't know what to do

Decision guide

Ask: "What is the ONE thing I want the user to do on this screen?"
→ That action gets type="primary"
→ Everything else gets default / link / text

Examples (one good, one bad — keep it focused)

// ✅ CORRECT — exactly ONE primary, the rest are default
<Space size={16}>
  <Button>Cancel</Button>                   {/* default — secondary */}
  <Button type="primary">Save</Button>      {/* primary — main CTA */}
</Space>

// ❌ WRONG — two primaries, user doesn't know which to click
<Space size={16}>
  <Button type="primary">Save Draft</Button>
  <Button type="primary">Submit</Button>
</Space>

Apply the same pattern to modals (Cancel + Confirm), destructive flows (Cancel + primary danger Delete), and toolbars (Filter/Export + primary Create). The principle never changes: one primary CTA per screen, everything else is default/link/text.

In Figma plugin code

// When placing multiple buttons, always identify the CTA first.
// QMAS has THREE separate Button component sets — pick the right key per role.
const QMAS_BUTTON_KEYS = {
  Primary: 'ea1bf5e1a1938d5470bab8292dcaa51ed0dd290a',
  Default: '513ffe289cdcf781eaf16e30543226c93ee91aae',
  Danger:  '25cd90c98741332e44ef4b26c9e3b422d5dc9b92',
};

const primarySet = await figma.importComponentSetByKeyAsync(QMAS_BUTTON_KEYS.Primary);
const defaultSet = await figma.importComponentSetByKeyAsync(QMAS_BUTTON_KEYS.Default);
const pick = (set: ComponentSetNode) => set.defaultVariant ?? (set.children[0] as ComponentNode);

// CTA gets Primary
const saveBtn = pick(primarySet).createInstance();
saveBtn.setProperties({ Label: 'Save' });
// ⚠️ REMINDER: any text node you modify INSIDE this instance must stay bound to a QMAS Text Style.
//    Use `setTextStyleIdAsync()` — do NOT set fontSize / fontName / fontWeight manually,
//    that detaches the token and is the v10 regression we're trying to prevent.

// Secondary gets Default
const cancelBtn = pick(defaultSet).createInstance();
cancelBtn.setProperties({ Label: 'Cancel' });
// ⚠️ Same rule: keep all text bound to QMAS Text Styles, all colors bound to variables.

MANDATORY RULE 9 — Text Case (Title Case + acronyms)

UI text in QMAS follows a strict Title Case principle. Misapplied case is the most common visual regression because Figma's built-in textCase = TITLE transform breaks acronyms (QC → Qc, Job ID → Job Id). Never use it. Write characters in their final cased form instead, and leave textCase = ORIGINAL.

Where Title Case applies (every word's first letter capitalised)

  • Section titles ("Create Production Order")
  • Field labels ("Production Module", "Quality Inspector")
  • Button labels ("Save Draft", "Submit For Review")
  • Chips / tags ("In Progress", "Awaiting Approval")
  • Table column headers ("Job ID", "Created Date", "Approver")
  • Left-side navigation items ("Production Orders", "QC Reports")

Where to keep the original case (NO conversion)

  • Descriptions / helper text — sentence case, as written ("Click to upload a CSV file.")
  • Input placeholders — sentence case, as written
  • Real data — names, emails, dates, IDs, team / module / supplier names display verbatim from the source

Acronyms STAY all-caps inside Title Case strings

Whenever a token is an acronym, do NOT case-fold it as part of title casing. Keep it all-caps:

✅ "QC Pass Rate"       ❌ "Qc Pass Rate"
✅ "Job ID"             ❌ "Job Id"
✅ "TCF Tracking"       ❌ "Tcf Tracking"
✅ "PO Status"          ❌ "Po Status"
✅ "Approve By PM"      ❌ "Approve By Pm"
✅ "ECD Forecast"       ❌ "Ecd Forecast"

Known QMAS acronyms to preserve all-caps: QC, IQC, QMAS, TCF, PO, ID, ECD, PM (extend per project).

Email / URL are always lowercase

✅ david.kim@company.com           ❌ David.Kim@Company.com
✅ https://qmas.icw.io/jobs/123    ❌ Https://Qmas.Icw.Io/Jobs/123

Inline formatting must survive case edits

When re-casing a string, touch ONLY letter case. Preserve: - Red required asterisk * (keep its original colour / fill) - Mixed-colour spans inside the string - Bolded sub-spans, links, etc.

Use a surgical edit — change only the letters whose case must shift. Do NOT overwrite the entire text block (that destroys the formatting).

Designer annotations are NOT UI — skip them

Canvas notes / annotations like *** Step 1 ***, Creation flow / Step 1, or any ***…*** callout are designer comments, not user-facing UI. Do not Title-Case them.

Figma plugin implementation — the right pattern

// ❌ WRONG — Figma's textCase = "TITLE" destroys acronyms (QC → Qc, Job ID → Job Id)
node.textCase = 'TITLE';

// ✅ CORRECT — write characters in the final cased form, leave textCase = ORIGINAL
const QMAS_ACRONYMS = ['QC', 'IQC', 'QMAS', 'TCF', 'PO', 'ID', 'ECD', 'PM'];

function smartTitleCase(s: string, acronyms = QMAS_ACRONYMS): string {
  return s
    .split(/(\s+|[-/])/)              // keep separators (space, dash, slash)
    .map(tok => {
      if (acronyms.includes(tok.toUpperCase())) return tok.toUpperCase();
      if (!/[a-zA-Z]/.test(tok)) return tok;          // numbers, punctuation untouched
      return tok[0].toUpperCase() + tok.slice(1).toLowerCase();
    })
    .join('');
}

textNode.characters = smartTitleCase('approve by pm');  // → "Approve By PM"
textNode.textCase   = 'ORIGINAL';                       // must stay ORIGINAL

React / CSS — write the final cased string in source

// ✅ CORRECT — source string already in Title Case with acronyms preserved
<Button type="primary">Save Draft</Button>
<Form.Item label="Job ID">{/* … */}</Form.Item>
<Table.Column title="QC Pass Rate" dataIndex="qcRate" />

// ❌ FORBIDDEN — CSS text-transform: capitalize has the SAME acronym bug as Figma TITLE
<Button style={{ textTransform: 'capitalize' }}>save draft</Button>
//                              ^^^^^^^^^^^^^^ this would mangle "QC" → "Qc" too

The rule pairs with Rule 8: the Primary CTA's label must ALSO follow Title Case ("Save Draft", not "save draft" or "SAVE DRAFT").

MANDATORY RULE 10 — App Shell (Header + Left Navigation are required)

Every QMAS page must wrap its content in the app shell: a fixed-height Header along the top and a fixed-width Left Navigation Sider down the side. These two components are non-negotiable for every authenticated page in the product — they are how users orient themselves and switch between modules.

When this rule does NOT apply (exceptions)

Only skip the shell for:

  1. Login / standalone auth pages — login, password reset, MFA prompts. These render full-bleed with at most a small centered logo. No header bar, no sider.
  2. Pop-up / overlay flows that visually cover the shell — a Modal, Drawer, Tooltip, Popover, or full-screen takeover. The shell is still rendered in the page underneath; it's just visually obscured by the overlay. Do not remove the shell from the DOM just because something is on top of it.

For literally any other QMAS page — list, detail, create-form, dashboard, settings, anything — Header + Sider are required.

Canonical Figma source

  • Header → Node 10754:29155 in T9HItYJ1nxXEJPiVF5xdxM. Default state: 1344 × 44, white surface, QMAS logo (60 × 24) left, 4 utility icons (chat / bell / settings / help, 24 × 24 each, 10-px padding, 24-px gap) + user name + email + 32 × 32 avatar (navy-100 circle) on the right.
  • Left Navigation → Node 10754:29156. Default state: 64 × full-height, navy-400 background. Hamburger toggle at top, three icon groups separated by hairline dividers (white at 1 px), each nav item 24 × 24 icon inside an 8-px-radius button with 22 × 10 padding. Active item full opacity; idle items 32 % opacity.

Always pull the live structure with get_design_context on those node IDs before building — don't rebuild from memory.

MANDATORY RULE 11 — Data Tables (the canonical table)

Tables drifted the most of any QMAS surface: every designer rebuilt one by hand, so column geometry, row heights, status chips, row actions and pagination all diverged. This rule ends that.

Canonical source of truth: file T9HItYJ1nxXEJPiVF5xdxM, page ↪ Table, section Table — QMAS Composed Patterns & States — 11 built state frames plus a spec card. Copy a frame from there. Never hand-build a table.

The anatomy (fixed — do not re-invent)

Content wrapper   VERTICAL · padding 24 · gap 16 · fill colorBgLayout
├── Toolbar Row     HORIZONTAL · h 40 · gap 16 · [title group] [Search] [FILL spacer] [primary CTA]
├── Filter Bar      HORIZONTAL · h 48 · padding 13/20 · gap 24 · radius 8
│                   fill colorBgContainer · 1px colorBorderSecondary · effect boxShadowTertiary

Column sizing — the one rule that prevents re-layout work

Every column is a FIXED px width except exactly one identity column, which is FILL. Removing or adding a column then re-flows automatically. Never hand-redistribute widths.

If a value clips, widen that fixed column — the FILL column absorbs the difference.

The 11 required states

Any table screen you deliver must account for all of these. Ship the ones the flow can reach.

  1. Default — sorted by the primary date descending, page 1 active.
  2. Search — Focused — Input State=active (focus ring), placeholder still showing.
  3. Search — Typing — value + clear icon, Dropdown Raw Menu of suggestions below, matched substring in Small/Strong.
  4. Search — Results — result bar (N results for "…" + Clear search), only matching rows, match highlighted, pagination total corrected to the result count.
  5. Search — No Results — Empty in the card, header row kept, Clear Search button.
  6. Filter — Dropdown Open — pill turns colorPrimary, caret flips up, .Filter panel below.
  7. Filter — Applied — pill reads Field: Value in colorPrimary, Reset becomes a live link (it is colorTextQuaternary until something is applied), result bar + filtered rows.
  8. Sort — Dropdown Open — pill active, menu of sortable fields, current field in colorPrimary with a check in the right slot.
  9. Row Selection — header checkbox indeterminate, selected rows filled colorPrimaryBg, bulk-action bar above the card stating the count + a Clear.
  10. Loading — skeleton per cell, pagination dimmed.
  11. Empty — Empty + the page's primary CTA; filter bar dimmed (nothing to filter).

Filter / sort / search division of labour

  • Toolbar pills own cross-cutting filters and the sort field. This is the QMAS default.
  • Column header menus (.Sorter / .Filter Button) are for per-column refinement only.
  • Do not ship both for the same field — pick one and be consistent across the module.
  • The search placeholder must name the fields it searches (Search product name, item no. or order no.), never a bare "Search".
  • Sorting by a status column sorts by workflow rank, never alphabetically.

Figma plugin gotchas (learned building this section)

  • setBoundVariableForPaint on a freshly created paint sometimes silently keeps its fallback colour, which renders black. When cloning rows, copy the fills array off a node that already renders correctly instead of re-creating the paint.
  • Setting a variant prop on a component instance (e.g. Input.setProperties({State:'active'})) invalidates references to its nested nodes. Re-query children after the swap.
  • importComponentSetByKeyAsync throws for dot-prefixed private components (.Sorter, .Filter, .Body Cell). Fetch those by node id in the token file.
  • Partial text formatting: use setRangeTextStyleIdAsync, not setRangeFontName, so the highlighted run still carries a QMAS text style and passes the binding audit.
  • Set layoutSizingHorizontal = 'FILL' after appendChild, and after any resize().
